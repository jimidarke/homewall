# Roku wall 0.12: 6×4 grid, 48 h temperature chart, live front PTZ camera

> **Status: approved 2026-10-07, in progress.** Design: `../specs/2026-10-07-roku-wall-6x4-design.md`.

## Context

The 0.11 Roku wall (6×3, cells 286×292) is taller than the tablet's landscape cards (242×171 dp, about 1.4:1). Calendar is a 286×604 sliver and Activity is 1×3. The user asked for:
- a 6×4 grid;
- Calendar and Activity at 2×2 each, stacked;
- Doors at 2×1;
- Activity at one line per row;
- the tablet's full 48 h outdoor temperature line chart in the Forecast card;
- the front PTZ camera playing live in the 2×2 camera square.

What the investigation found:
- **HAku's `front` stream points at a camera that no longer exists.** It's an Amcrest at `.35`, and go2rtc reports "no route to host".
- **HA's front PTZ camera** is a Genbolt dual-lens camera at `192.0.2.31`. Its PTZ lens is RTSP `/21`, HEVC 1920×1080 at 15 fps, and the login is in HA `secrets.yaml` as `genbolt_ptz_stream`.
- **The Rokus need H.264,** so go2rtc must re-encode with QSV.
- **The user will** move the camera and dismiss the NVR's Alarm menu themselves.
- **Backyard (`.34`) is offline** and out of scope.

**Execution step 0:** commit this as two documents, and keep them in step with each other:
- spec: `docs/superpowers/specs/2026-10-07-roku-wall-6x4-design.md`
- plan: `docs/superpowers/plans/2026-10-07-roku-wall-6x4.md`

## Layout (config only, `layouts.roku`)

**Grid:** `{cols 6, rows 4, cellW 289, cellH 220, originX 52, originY 116, gap 16}`.
- The grid ends at x 1866 and y 1044. The clock's bottom edge is at y 106.
- Card body = tile minus chrome. The chrome is trimmed to `TILE_BODY_Y` 84 and `TILE_PAD_BOTTOM` 12, so the extra 12 px go to the body.
- A 1×1 body is 249×124. A 2×1 body is 554×124. A 2×2 body is 554×360.

```
      c0         c1       c2   c3        c4   c5
r0   [ Doors (2×1)  ]    [ Calendar ]   [ Front    ]
r1   Laundry    Water    [          ]   [ (live)   ]
r2   Energy     Gas      [ Activity ]   [ Forecast ]
r3   Weather    Thermo   [          ]   [ 3-day +  ]
                                        [ 48 h     ]
```

- **Every entry gets its own `tile`.** The ref merge is shallow, so `tile` replaces the tablet's tile entirely. This means Roku tiles no longer follow tablet moves.
- **Calendar:** `{"ref":"tablet:calendar","tile":{"type":"agenda","col":2,"row":0,"w":2,"h":2,"dropHeaders":false}}`.
- **Activity:** `timeline` uses the same shape, with `dropHeaders: true`.
- **Camera:** `{"ref":"cameras","title":"Front","tile":{"type":"camera","col":4,"row":0,"w":2,"h":2,"cam":"front"}}`.
- **Forecast:** as it is today, plus `"tile": {"type":"forecast","col":4,"row":2,"w":2,"h":2,"card":"/api/card/weather_chart.png"}`. The chart path goes in `tile`, because `hkSlimConfig` keeps `tile` but drops `drill`.

## 1. Stream: front → Genbolt PTZ (`stream/`)

- **`go2rtc.yaml`:** replace the `front` source with an `exec:ffmpeg` QSV re-encode, in the same style as the mosaic:
  - input: `-rtsp_transport tcp -i rtsp://${HAKU_FRONT_USER}:${HAKU_FRONT_PASSWORD}@192.0.2.31:554/21`
  - decode: `-hwaccel qsv -c:v hevc_qsv`
  - scale: `vpp_qsv` or `scale_qsv` to 1280×720
  - encode: `h264_qsv`, main profile, `-g 30 -keyint_min 30 -bf 0` (2 s GOP, matching the 2 s HLS segments), about 2 Mbps CBR, `-an`, `-f rtsp {output}`
  - It reads the camera directly, with no intermediate `front_src` stream, which would otherwise leak into discovery.
  - Update the front/HEVC comments.
- **Separate login variables:** `HAKU_FRONT_USER` and `HAKU_FRONT_PASSWORD` in `/etc/haku/cam-creds.env`.
  - Append them on nserver, piping the values from mserver's `secrets.yaml` without printing them.
  - Never re-run the README's creds step: it overwrites the file with a placeholder.
- **`haku-discovery.py` `STREAM_METADATA["front"]`:** `displayName "Front"`, `vendor "Genbolt"`, `ptz True`, `codec "h264"`, `resolution "1280x720"`, `audio False`. The JSON shape doesn't change, so there's no schemaVersion bump.
- **`haku-hls@.service`:** unchanged. It uses `-c copy`, which is fine once the stream is H.264.
- **Docs:**
  - Update `stream/README.md` (endpoints table, the stale Phase 2 snippet) and `docs/HAKU_DESIGN.md` (front inventory and stream rows).
  - **Scrub the plaintext camera password at `docs/HAKU_DESIGN.md:791`.** Tell the user it is still in git history.
- **`roku/tests/fixtures/discovery.json`:** update the front metadata.

**ForecastBody chart image:**
- The URL is `hkWithLayout(hkHubCardUrl(hubBase, card, w, h, v), HK_LAYOUT())`, with `v` as a 5-minute time bucket. Include `Api.brs`.
- Two Posters swapped on `loadStatus = "ready"`, as `BackgroundGallery` does, so the chart never blanks while it reloads. Set the uri only when it changes.

**CameraBody (new, `components/CameraBody.{xml,brs}`):**
- **Children:** a Video placed with `hkVideoFit`, muted with `live=true` (HLS content built the same way as LiveGroup's), and an offline label "Camera offline" with the cctv glyph.
- **Fields:** the usual body fields, plus `streams`, `active`, and an output `hasStream`.
- **Behaviour:**
  - While `active` and a URL exists: play.
  - On an error: back off with `hkNextBackoffSeconds`.
  - After 4 straight errors: rest for 5 min. Show the offline label and play `pkg:/images/keepawake.mp4` invisibly on the **same** Video node, so the screensaver stays away and there's still only one decoder. Then retry.
  - A stall watchdog restarts playback if it hasn't been playing for 90 s.
  - When `active` goes false: stop and kill the timers.
  - Emit `hwEvent("home_cam", {state, cam})`.

**Plumbing:**
- `HomeGroup`: new `hubBase`, `streams` and `camActive` fields, passed to the tiles, and an output `hasCam`.
- `MainScene`: set `home.hubBase` and `home.streams` alongside `m.modules.hubBase` and `m.live.streams`, both in `onDiscoveryResult` and from the cache in `init`.
- `MainScene.syncHomeDecoder()`, called from `goHome` and when `home.hasCam` changes:
  - on home with a camera: `stopKeepAwake()` and then `home.camActive = true`;
  - otherwise: `camActive = false` and keep-awake as today.
- `goLive`, `enterGrid`, `goModule` and `goDiag` set `home.camActive = false` **before** any other playback starts.
