# Tablet UI v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give the kitchen tablet its own sidecar layout without cameras, and a house-activity-first 4×3 smoked-glass card UI. It adds MDI iconography, NAS photo backgrounds with fake frosted glass that works on API 30, calm one-shot motion when activity starts or stops, and night dimming.

**Architecture:**
- **Sidecar** (`~/code/roku-homewall/server/sidecar`, Python/Flask):
  - per-display layouts (`?layout=tablet`);
  - additive tile keys `glyph`, `active` and `level`;
  - `doors` and `laundry` modules;
  - per-layout background folders with `fit=cover` and `blur`.
- **Tablet** (`~/code/tablet-homewall`, Kotlin/Compose):
  - polls the layout and projects each poll into `@Immutable` card models in the ViewModel;
  - draws cards over a cross-fading photo backdrop, where each card draws its own region of a pre-blurred low-res copy.

**Tech Stack:** Kotlin 2.1.20, Compose BOM 2025.02.00 (Material3 1.3.1), AGP 8.7.3, OkHttp 4.12, kotlinx.serialization 1.7.3, JUnit 4. Python 3.12, Flask 3, Pillow, pytest.

**Spec:** `~/.claude/plans/lets-take-this-to-curious-phoenix.md` (approved 2026-09-30). The exact values live in `docs/superpowers/plans/2026-09-30-tablet-ui-v2-contract.md` (the **Contract**). Existing approved design: `docs/DESIGN.md`.

## Global Constraints

**Toolchain and dependencies**
- Do not bump AGP, Kotlin, the Compose BOM or Gradle. Builds must resolve from the existing Gradle cache, so use `--offline`.
- **No new libraries.** No Coil, Glide, Haze, Palette, material-icons, DI or WebView. The only additions are the Barlow font files and MDI path data.
- minSdk stays 30 (Fire OS 8). Nothing may need API 31+, which rules out `RenderEffect`, `Modifier.blur` and dynamic colour.
- Cleartext HTTP stays limited to `192.0.2.20`. Do not touch `network_security_config.xml`.

**Contract rules**
- **The sidecar owns formatting.** The tablet renders `hero/sub/detail/status/age` strings as given.
- Unknown JSON keys are ignored. An unknown `tile.type` falls back to `ValueCard`.
- **Roku safety:**
  - Default `/api/config` and `/api/state` (no `layout`) stay byte-for-byte the same, apart from the additive tile keys `glyph`/`active`/`level` and `items[].glyph`.
  - `layouts` must never appear in the default `/api/config`, because the Roku registry caps config at about 16 KB.

**Visual rules**
- Colours, sizes and timings come from Contract §3 verbatim. Text is never below 16 sp, and `fontScale` is locked to 1.
- Nothing animates while the house is quiet. The only looping animation is the laundry LEDs in animated modes, at 10 fps or less.

**Ways of working**
- **Device rule:** never sleep or wake the tablet. Verify only with `adb -s $TABLET_SERIAL exec-out screencap -p > shot.png`. Installing is `adb -s $TABLET_SERIAL install -r app/build/outputs/apk/debug/app-debug.apk`.
- **Test commands:**
  - tablet: `cd ~/code/tablet-homewall && ./gradlew testDebugUnitTest --offline`
  - sidecar: `cd ~/code/roku-homewall && server/sidecar/.venv/bin/python -m pytest server/sidecar/tests -q`
- **Commits:** Conventional Commits, ending with the trailer `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- **Branches:** tablet `feat/ui-v2`, sidecar repo `feat/tablet-layouts`. Never push.
- **Logging:** tablet logcat tag `KitchenWall`, as `event=<name> k=v` lines.

## Review Focus

1. **Sidecar unreachable, or the NAS unmounted, at cold start or mid-run.** The app shows Connecting, the gradient or the last photo, and never crashes or blanks. Owned by Tasks 2, 17 (loader tests) and 18 (offline).
2. **A long sidecar string**, such as "Washer running 25m long" or "Bathroom door". It must fit on one line by shrinking (FitText) or ellipsize, and never overflow the card. Owned by Task 10 (FitText test) and Task 11.
3. **An HA or sidecar restart, where modules come back `stale`, then fresh.** There must be no pulse storm, and stale cards dim. Owned by Task 4 (`pulses()` tests).
4. **A Roku default response.** No `layouts` key, and identical bytes with or without a `layouts` block in the config. Owned by Task 6 (regression tests).
5. **A night window that wraps midnight, and the date changing while the app runs.** `isNight` handles the wrap and the clock rolls over correctly. Owned by Task 5 (`isNight` tests).

**SidecarClient**
- Build every URL with OkHttp `HttpUrl`: `base.toHttpUrl().newBuilder().addPathSegments("api/config")`, then `addQueryParameter("layout", layout)` when `layout != null`. The same applies to `api/state` and `api/backgrounds`.
- The background URL is `addPathSegments("api/background").addPathSegment(name)` plus `layout`, `w`, `h` and `fit`, with `blur` added only when it is > 0.
- `backgrounds()` parses `{"images":[{"name":…}]}` to `List<String>`. Entries with no `name` are skipped; a missing `images` key gives an empty list.
- `background()` returns the raw bytes. A non-2xx response is `HttpError`, an `IOException` is `NetworkError`, and nothing throws.

**DemoSource**
- `config()` reads `read("demo/config.json")` and returns `HubJson.parseConfig(...)`.
- `state()` reads `read("demo/<s>.json")`. `s` is `scenario`, except for `scenario == "cycle"`, where it is `listOf("quiet","busy","alert")[((clock() / 10_000) % 3).toInt()]`.
- `backgrounds()` and `background()` delegate to `real`.
- A failed read or parse returns `Fetch.ParseError`.

**Demo JSON** (`app/src/debug/assets/demo/`)
- `config.json` is exactly the Contract §1.1 config.
- `quiet.json`, `busy.json` and `alert.json` are full Contract §1.2 states for all 9 feed keys, with realistic values:

|---|---|
| `quiet.json` | everything idle: doors closed, laundry idle, water not running, climate idle |
| `busy.json` | washer running (3 leds, "34m left"), dryer `done_calm`, back door open 2m (`severity` normal, `active` true), water running, climate heating (glyph `fire`, `active` true), 8 timeline events with glyphs, 4 calendar items with headers and `dot` |

```kotlin
@Immutable sealed interface CardModel { val id: String }
@Immutable data class ValueModel(
    override val id: String, val kind: String, val title: String, val glyph: String,
    val hero: String, val sub: String, val detail: String,
    val alert: Boolean, val active: Boolean, val level: Int?, val stale: Boolean,
    val pulseSeq: Int = 0, val pulseCount: Int = 0,
) : CardModel
@Immutable data class DoorsModel(val base: ValueModel, val doors: List<Door>) : CardModel { override val id get() = base.id }
@Immutable data class LaundryModel(val base: ValueModel, val machines: List<Machine>) : CardModel { override val id get() = base.id }
@Immutable data class AgendaModel(
    override val id: String, val kind: String, val title: String, val glyph: String,
    val items: List<AgendaItem>, val activity: Boolean, val stale: Boolean, val highlightAfter: Long?,
) : CardModel

data class Signal(val active: Boolean, val alert: Boolean, val stale: Boolean)
enum class Pulse { ACTIVE, ALERT }
fun signals(cards: Map<String, CardModel>): Map<String, Signal>          // Value/Doors/Laundry only; Agenda excluded
fun pulses(prev: Map<String, Signal>?, next: Map<String, Signal>): Map<String, Pulse>
fun project(config: HubConfig, state: HubState, pulseSeq: Map<String, Int> = emptyMap(),
            pulseKind: Map<String, Pulse> = emptyMap(), highlightAfter: Map<String, Long?> = emptyMap()): Map<String, CardModel>
```

**`project` rules** (one entry per `config.modules`, keyed by `ModuleDesc.id`, with state read by `ModuleDesc.key`)
- **Which model:**
  - `kind == "doors"` and `state.doors(key) != null` → `DoorsModel`.
  - `kind == "laundry"` and `state.laundry(key) != null` → `LaundryModel`.
  - else `tile.type == "agenda"` → `AgendaModel`, with `activity = tile.dropHeaders` and `items = state.items(key, tile.dropHeaders)`.
  - else → `ValueModel`. **This includes unknown types.**
- **ValueModel fields:**
  - hero, sub, detail, glyph, active and level come from `state.tile(key)`. A missing tile gives `hero = "—"` and blanks.
  - `alert = severity == "high"`; `stale = state.stale(key)`.
  - `title` is the module title.
  - `pulseSeq = pulseSeq[id] ?: 0`.
  - `pulseCount`: `ALERT` → 2, `ACTIVE` → 1, none → 0.
- **AgendaModel:** `glyph` comes from the tile.

**`pulses` rules**
- `prev == null` → empty.
- For each id in `next` that is also in `prev`:
  - skip it if either side is stale;
  - `!p.alert && n.alert` → `ALERT`;
  - otherwise `!p.active && n.active` → `ACTIVE`.

**ViewModel**
- New state: `data class UiState(val sidecar: String, val config: HubConfig? = null, val cards: Map<String, CardModel> = emptyMap(), val error: String? = null)`.
- Remove `state: HubState?` and `lastOkAt`. Expose `val lastOkAt: StateFlow<Long?>` separately. It is used by freshness and the banner in Task 5; until then `Dashboard` reads it via `collectAsStateWithLifecycle`.
- **Poll loop**, on every OK state:
  1. Compute `cards0 = project(cfg, st)` and `sig = signals(cards0)`.
  2. Compute `fired = pulses(prevSignals, sig)` and increment `seq[id]` for each fired id.
  3. Compute `cards = project(cfg, st, seq, fired, highlightAfter)`.
  4. Set `prevSignals = sig`.
  5. `_ui.update { it.copy(cards = cards, error = null) }`.
- **On a failed poll:** set `prevSignals = null` and leave the cards alone.
- **highlightAfter** (per agenda id) is the previous successful poll's newest item `whenTs`, or null after a gap or a cold start.
- **Projection runs on `Dispatchers.Default`.**
- **UI:** `Dashboard` and `Tiles.kt` render from `ui.cards[m.id]`. `ValueTile` takes a `ValueModel`, and `AgendaTile` takes an `AgendaModel`; `DoorsModel` and `LaundryModel` render through `ValueTile(model.base)`. There is no visual change in this task.

**Implementation notes**

- **Grid geometry:** `cellW = (width - left - right - gap*(cols-1)) / cols`, and likewise `cellH` from height, top and bottom. `x = left + col*(cellW+gap)`, `y = top + row*(cellH+gap)`. Spans are clamped as today.
- **Freshness:** use `transformLatest` on `lastOkAt`. Emit `freshness(t, now)`, then `delay` until the next boundary (`t + LAGGING_AFTER_MS` or `t + OFFLINE_AFTER_MS`), then stop at OFFLINE. Use `stateIn(viewModelScope, SharingStarted.Eagerly, Freshness.OFFLINE)`.
- **Night:** `combine(ui.map{it.config?.nightDim}.distinctUntilChanged(), minuteTicker)`. The ticker emits at each minute boundary.
- **Dashboard:**
  - Remove the 1 s `produceState` ticker. The header uses `Clock()` and the dot reads `vm.freshness`.
  - Wrap the grid loop in `key(m.id) { … }`.
  - Use `tileRect(..., GridArea(maxWidth, maxHeight, MARGIN_DP, HEADER_DP, MARGIN_DP, MARGIN_DP, GAP_DP))`, where the grid's `BoxWithConstraints` now fills the whole screen.
- **MainActivity:** `lifecycleScope.launch { repeatOnLifecycle(STARTED) { vm.night.collect { n -> window.attributes = window.attributes.apply { screenBrightness = if (n) vm.nightBrightness else WindowManager.LayoutParams.BRIGHTNESS_OVERRIDE_NONE } } } }`.
